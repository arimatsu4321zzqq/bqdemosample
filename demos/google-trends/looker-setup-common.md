# Looker Studio ダッシュボード共通セットアップ手順（P1〜P3 共通の土台）

「検索トレンド 地域ビュー」を手動構築するための**最初に1回だけ行う共通設定**。
各ページ手順書（`looker-page-P1〜P3`）はこのファイルを前提にする。機能の可否の根拠は
[`../../docs/looker-studio-capabilities.md`](../../docs/looker-studio-capabilities.md) を参照。

- 対象プロジェクト: `ci-ss4-develop` / データセット: `demo_google_trends`（ロケーション **US**）
- 使うテーブル（[`setup.md`](./setup.md) 手順3で作成済み）:
  - `jp_region_weekly` … 県×週×ワードの明細（177万行・約100MB）。時系列・順位・KPI。
  - `jp_term_region_weeks` … ワード×県のランクイン週数（3.5万行）。P2 の県別チャート（定番・県間比較）用。
- レイアウトの実物イメージ: [`mock/`](./mock/)

---

## STEP 0. レポート作成
1. https://lookerstudio.google.com → 「空のレポート」を作成。
2. レポート名を **「検索トレンド 地域ビュー」** に変更。

## STEP 1. データソースを2本追加（テーブル選択方式）
「リソース → 追加済みのデータソースの管理 → データを追加 → BigQuery」から、以下を**2回**繰り返す。
1. 認証 → プロジェクト `ci-ss4-develop` → データセット `demo_google_trends` → テーブル選択。
2. 対象テーブル: `jp_region_weekly` / `jp_term_region_weeks`。
3. 各データソースの名前を分かりやすく: **`週次明細`** / **`週数集計`**。

> 177万行だが実体は約100MBなので直結でよい（Extract 不要）。

## STEP 2. フィールドの型・既定集計を設定（★最重要）

### 週次明細（jp_region_weekly）
| フィールド | 設定 | 備考 |
|---|---|---|
| `week` | 日付 | 時系列の軸 |
| `score` | 既定の集計 = **平均 (AVG)** | SUMのままだと桁が壊れる |
| `latest_rank` | 既定の集計 = **最小値 (MIN)** | 1が最上位。SUM/AVG禁止 |
| `is_latest_week` | 真偽値 | 「最新週」フィルタの要 |
| `region_name` / `term` | テキスト | region_name は英語表記（→STEP2-3で日本語化） |
| `region_code` | （任意）地域 → 国内地域第1レベル | 地図は原則使わないが、使う場合はこれ |

### 週数集計（jp_term_region_weeks）
| フィールド | 設定 | 備考 |
|---|---|---|
| `ranked_weeks` | 既定の集計 = **合計 (SUM)** | 県横断で足すと全国のべ週数になり整合 |
| `total_weeks` | 既定の集計 = **最大値 (MAX)** | ワード単位の定数のため |
| `share` | 既定の集計 = **最大値 (MAX)** | 単一県・単一ワードで見る前提の定数 |
| `is_local_term` | 真偽値 | ※地元ワード廃止によりダッシュボードでは未使用（列自体は残置。無視してよい） |

### STEP 2-4. 月の計算フィールド（週次明細のみ・P2の季節性用）
**`month`** = `MONTH(week)`（数値。1〜12）。

## STEP 3. テーマ・キャンバス（全ページ共通の見た目）
- 「テーマとレイアウト → テーマ」でカスタムテーマを作成（[`mock/`](./mock/) の配色に合わせる）:
  - アクセント（棒・強調）: `#2A78D6`（青） / 補助: `#1BAF7A`（青緑）・`#EDA100`（黄土）
  - 背景 `#F7F8FA` / パネル `#FFFFFF` / 文字 `#12161C`
- **キャンバスサイズ**: 幅 1366 × 高さ 768。チャートヘッダー「ホバー時に表示」。グリッドスナップ ON。

## STEP 4. ページ構成とナビゲーション
1. ページを3枚: **P1 地域ビュー** / **P2 ワード深掘り** / **P3 全国サマリ**。
2. 「テーマとレイアウト → レイアウト → ナビゲーションタイプ」= **タブ**。
3. 各ページ上部に共通ヘッダー帯。P1で作って全ページへコピペ。

## STEP 5. レポートレベルの共通部品
- テキスト部品で **「スコアは各ワードの自己ピーク=100の相対値（ワード間・県間の大小比較は不可）」**
  の注記をフッターに置き、「レポートレベルにする」で全ページ表示。
- 最新週の表示: スコアカード（週次明細 / MAX(week)）を小さくヘッダー横に置くと「毎週更新」が伝わる。

## 補足: このダッシュボード固有の注意（★ハマりどころ）

1. **コントロールを両データソースに効かせる（フィールドID統一・★構築前に必ずやる）**:
   フィルタコントロールは**フィールドIDが一致すれば別データソースのチャートにも効く**（公式仕様。
   capabilities 5節）。本レポートでは1つの都道府県▼・ワード▼で両ソースを絞るため、STEP 2-3 で
   `県名` を両ソースに作った直後に、**「リソース → フィールド名とIDの管理 → フィールドの上書きを追加」で
   両ソースの `県名` に同じID（例: `pref_ja`）を割り当てる**。`term` は同名の元カラムでIDが一致する
   はずだが、コントロールが片方に効かない場合は同様にIDを統一する。
   ⚠ **使用中フィールドのID変更はチャートを壊す**ため、この作業はチャートを1つも作る前に済ませる。
   **ブレンドは使わない**（本ダッシュボードの方針。チャートは常に単一データソースで作る）。
   万一ID統一がうまく動かない環境では、フォールバックとしてコントロールをデータソースごとに
   2つ隣接配置する（ラベルで「県(明細)/県(集計)」と区別）。
2. **期間コントロールは置かない**（旧設計と違い「最新週」は is_latest_week フィルタで固定。
   時系列は全期間表示が既定で、期間を絞る要件が出たら追加する）。
3. `latest_rank` は最新週以外 NULL（仕様）。順位を使うチャートには必ず
   `is_latest_week = true` のチャート単位フィルタを併用する。
4. 「急上昇」「NEWバッジ」（4週前比）は Looker の計算フィールドでは作れない。
   必要になったら `jp_term_region_weeks` の SQL に gain 列を追加してから対応する（現状スコープ外）。
