# Looker Studio できることリファレンス（手動ダッシュボード構築用）

BigQuery の検索トレンドデータで4ページのダッシュボードを手動構築するための、Looker Studio 機能リファレンス。公式情報（support.google.com/looker-studio, cloud.google.com/looker/docs, developers.google.com）に基づく。末尾の「出典」「確認事項」を必ず参照すること。

用語: **ディメンション**=分類軸（例: 都道府県, 日付, キーワード）。**指標(メトリック)**=数値（例: 検索数）。両者を合わせて「フィールド」と呼ぶ。

---

## 1. データソース接続（BigQuery）

### テーブル選択 vs カスタムクエリ
- **BigQuery コネクタ**でデータソースを追加する流れ:「リソースの管理 / データを追加」→ 「BigQuery」コネクタ選択 → 認証 → プロジェクト → データセット → テーブルを選ぶ、または「カスタムクエリ」タブで SQL を書く。
- **テーブル選択**: テーブルを直接指定。Looker Studio がフィールドの集計・キャッシュを効率的に扱いやすい。可能ならこちらを推奨。
- **カスタムクエリ**: SQL を自由記述。最も柔軟だが、パラメータ化やキャッシュ効率で不利になりやすい（新規クエリが毎回発行され得る）。集計を SQL 側で済ませて行数を減らすのに有効。

### データの鮮度（キャッシュ）
- BigQuery データソースの**既定のデータ鮮度は 12 時間**。データソース編集画面の「データの鮮度」で変更可能。
- 過去に発行済みで鮮度しきい値内のクエリはキャッシュから返り、パフォーマンス向上・BigQuery コスト削減になる。ただし**キャッシュヒットは保証されない**（新規クエリや鮮度切れで BigQuery に再クエリ）。パフォーマンス確保はキャッシュに依存せず、後述の Extract や BI Engine を使う。

### 抽出（Extract）データソース
- 既存データソースを元に**静的スナップショット**を作る仕組み。表示が速くなる。
- **上限は 1 抽出あたり 100MB**。超えても**エラーは出ず、データが不完全になる**（サイレントに欠落）ので、フィールドを絞る/集計する/期間を限定して 100MB 以内に収める。
- 更新: 「自動更新」をオンにし、**日次 / 週次 / 月次**のスケジュールを設定。次の更新までデータは静的（リアルタイム用途には不向き）。
- 検索トレンドのような集計済み・履歴データには Extract が有効。

## 2. チャート種類一覧と必須/主要フィールド

すべてのチャートは**最低1つの指標**が必要（表・散布図など一部はディメンションも実質必須）。「内訳ディメンション(breakdown)」は系列を分割する軸。以下、用途 / 主要フィールドの順。

- **スコアカード (Scorecard)**: 単一指標のサマリー表示（KPI）。指標=1つのみ。ディメンションなし。期間比較（前期比など）や省略記数（コンパクト表示）を設定可。
- **期間 / 時系列 (Time Series)**: 時間推移。X軸=日付(期間ディメンション)、指標=1つ以上、内訳ディメンション=系列分割（任意）。スパークライン・スムージング変種あり。検索トレンドの主役。
- **折れ線 (Line)**: 時系列の一種。ディメンション=X軸、指標=1つ以上、内訳=系列。
- **棒 / 縦棒 / 積み上げ棒 (Bar/Column)**: カテゴリ比較。ディメンション=カテゴリ、指標=1つ以上、内訳=積み上げ/グループ分割。積み上げ・100%積み上げ変種あり。
- **コンボ (Combo)**: 棒＋折れ線の混在。ディメンション=X軸、指標=複数（各系列を棒か線に指定）。
- **円 / ドーナツ (Pie/Donut)**: 全体に対する構成比。ディメンション=1つ（スライス）、指標=1つ。カテゴリ数は絞る。
- **表 (Table)**: ソート・ページング可能な明細/集計。ディメンション=複数可、指標=複数可、並べ替え=任意指標で昇降順。棒付き表・ヒートマップ表の変種あり。行制限を設定可。
- **ピボット表 (Pivot Table)**: 2軸クロス集計。行ディメンション＋列ディメンション＋指標。行・列両方向で比較。
- **面 (Area)**: 時系列の面表現。ディメンション=X軸、指標=1つ以上。積み上げ・100%積み上げ変種。
- **散布図 / バブル (Scatter/Bubble)**: 2変数の相関。X指標＋Y指標（各1）、バブルは第3指標=サイズ、色ディメンション=バブル色（任意）。ディメンション=各点（任意）。
- **ツリーマップ (Treemap)**: 階層/構成比を面積で。ディメンション=階層（複数でドリル）、指標=面積（＋色に別指標）。
- **ゲージ (Gauge)**: 目標に対する達成度。指標=1つ、範囲(min/mid/max)を設定。
- **ブレット (Bullet)**: 目標レンジに対する進捗。指標=1つ＋レンジ。
- **地域別マップ / Geo チャート (Geo Chart)**: 国/大陸/地域の塗り分け。地理ディメンション=1つ、色指標=1つ、ズームエリア(表示範囲)を選択。→ 第3節参照。
- **Google マップ (Google Maps)**: バブル/塗り分け(filled)/ヒートマップ/ライン。位置ディメンション（緯度経度 or 住所 等）＋指標。→ 第3節参照。
- **ローソク足 (Candlestick)**: 高安始終値。
- **コミュニティビジュアル (Community Visualizations)**: サードパーティ製（サンキー、ワードクラウド、ファネル 等）。→ 第9節。

（ドキュメント上「Sankey / Waterfall / Boxplot / Timeline / Funnel」等も種類一覧に登場するが、環境により標準搭載かコミュニティ版か差があるため、実機で確認）

## 3. 地図（Geo チャート / Google マップ）— 重要

### サポートされる地理ディメンション型（Geo dimension reference より）
1. **大陸 (Continent)**: 3桁コード(例 001) or 名称
2. **サブ大陸 (Subcontinent)**: 3桁コード or 名称
3. **国 (Country)**: ISO 3166-1 alpha-2/alpha-3 or 国名
4. **国内地域・第1レベル (Country Subdivision 1st level)**: 都道府県・州・県など
5. **国内地域・第2レベル (2nd level)**: 郡など（**Google マップのみ**）
6. **指定マーケットエリア (DMA)**: 米国メディア市場のみ
7. **市区町村 (City)**: Geo target ID or 都市名
8. **郵便番号 (Postal Code)**: 米国 ZIP or 国際郵便番号
9. **住所 (Address)**: 完全な住所（**Google マップのバブルマップのみ**）
10. **緯度・経度 (Latitude/Longitude)**: `"緯度,経度"` のカンマ区切り小数（例 `"35.68,139.76"`）

### 日本の都道府県（第1レベル）塗り分け — 可否
- **公式に「日本の都道府県」は第1レベル国内地域(Country Subdivision 1st level)としてサポート対象**。公式 Geo dimension reference が**例として `JP-13`(東京), `JP-23`(愛知)** を挙げている。
- 受け入れられる**エンコード形式**（第1レベル）: **ISO-3166-2 コード**（例 `US-AL`, `JP-13`）／米国 FIPS／英国 NUTS 1／**地域名(subdivision name)**。
  - ただし **Geo チャートは FIPS/NUTS を非サポート**。Geo チャートでは **ISO-3166-2 コード or 地域名**を使う。
- Geo チャート（地域別マップ）は内部的に Google Charts の **GeoChart** を利用。GeoChart は `region:'JP', resolution:'provinces'` で**日本の都道府県塗り分けをサポート**しており、**英語の都道府県名（"Tokyo","Hokkaido"…）または `JP-xx` コード**を受け付ける（開発者向け GeoChart ドキュメント／複数実装事例で確認）。
- **設定手順の要点（Geo チャート）**: 地理ディメンションに都道府県フィールド（`region_code=JP-13` 形式が最も確実）→ フィールドの型を「地域(Region / 国内地域第1レベル)」に指定 → 色指標を設定 → **ズームエリア(表示範囲)を「日本」または「地域(Region)」に設定**（世界のままだと都道府県が見えない）。
- **代替案（塗り分けが不安定な場合）**:
  - **Google マップのバブルマップ**: 各都道府県の**緯度経度**を用意して点＋サイズ/色で表現。境界データに依存せず確実。
  - **Google マップの塗り分け(filled)/ヒートマップ**。
  - BigQuery の GEOGRAPHY ポリゴンを Google マップで描く方法もある。

### Geo チャートのスタイル
- 色の最大値/中間値/最小値/データなし色を設定。値の高低を色の濃淡で表現。
- ズームエリアは選択した地理型に応じて World / Continent / Subcontinent / Country / Region から選べる。

### Google マップ
- **位置(Location)フィールドが必須**（緯度経度型、住所型、または地理ディメンション）。バブル=サイズ/色に指標。**Google マップはオプション指標(optional metrics)非対応**。
- 緯度経度の精度は**小数5〜6桁程度に丸める**のが推奨。

## 4. 計算フィールド

### 作り方
- データソース編集画面で「フィールドを追加」、またはチャート設定内で計算フィールドを作成。データソースレベル（全チャート共有）とチャートレベル（そのチャートのみ）がある。

### 主要関数（Function list より）
- **集計**: `SUM`, `AVG`, `COUNT`, `COUNT_DISTINCT`, `MIN`, `MAX` など。
- **条件**: `CASE WHEN … THEN … ELSE … END`。`REGEXP_MATCH(field, "正規表現")` と併用してグルーピング可。
- **正規表現**: `REGEXP_MATCH`, `REGEXP_EXTRACT`, `REGEXP_REPLACE`。特殊文字のエスケープは**バックスラッシュ2つ**（例 `REGEXP_MATCH(x, "\\*")`）。
- **日付**: `DATE`, `YEAR`, `MONTH`, `WEEK`, `DATETIME_DIFF`, `TODATE` など。時系列の粒度変換に使用。
- **地理**: `TOCITY`, `TOCONTINENT`, `TOCOUNTRY`, `TOREGION`, `TOSUBCONTINENT`（値を地理型に変換）。緯度/経度の抽出関数 `LATITUDE` / `LONGITUDE` は Function list で要確認（→ 確認事項）。
- **文字列/数値**: `CONCAT`, `LOWER/UPPER`, `ROUND`, 算術演算子など。

### 集計 vs 非集計（重要ルール）
- **1つの計算式で集計データ(指標)と非集計データ(ディメンション)を混在できない**。
  - 例: `CASE WHEN Country="England" AND Conversions>100 THEN …`（`Conversions` は集計指標）は**無効**。
- **非集計の計算フィールド**（ディメンション単位、行ごとに評価）と、**集計計算フィールド**（`SUM(...)`等を含み指標になる）を区別して設計する。

## 5. フィルタ & コントロール

### コントロール（閲覧者が操作する部品）
- **ドロップダウンリスト**: 単一/複数選択。値の多いディメンション向け。
- **固定サイズリスト (fixed-size list)**: 常時展開されたリスト。
- **入力ボックス (検索ボックス)**: テキストで絞り込み。
- **高度なフィルタ (advanced filter)**: 含む/等しい等の条件入力。
- **チェックボックス (tickbox)**。
- **スライダー (slider)**: 数値レンジで絞り込み（指標スライダー）。
- **期間コントロール (date range control)**: カレンダーで表示期間を変更。
- **データコントロール (data control)**: 閲覧者が自分のデータソースに切替（GA等）。

### フィルタの適用範囲（スコープ）
- **レポート単位**: レポート全体に適用（全ページ）。
- **ページ単位**: そのページの全チャートに適用。
- **チャート単位**: 個別チャートにのみ適用。
- コントロールも配置場所（ページ or レポートレベル）と「コントロールのグループ化/適用対象」で影響範囲が決まる。手順書では「期間コントロールはレポートレベルに置いて全ページ共通」等を明記すると良い。

## 6. インタラクション

- **ドリルダウン/ドリルアップ**: 1つのチャートに複数ディメンションを階層登録し、クリックで粒度を上下（例: 国→都道府県→市）。**そのチャート内のみ**で完結し他チャートに影響しない。
- **クロスフィルタリング（相互作用）**: あるチャートで値をクリック/範囲選択すると、**同一キャンバス上の関連チャート全体**が絞り込まれる。チャート設定で「クロスフィルタリング」をオンにする。ドリルダウンと併用可。
- **オプションの指標 (optional metrics)**: 閲覧者/編集者がチャート編集なしに表示指標を選択。
- **オプションのディメンション**: 同様にディメンションを選択可。
- **注意**: **指標スライダーとオプション指標は同一チャートで併用不可**。
- **リンク・ページ遷移**: テキスト/画像/ボタンにURLリンクや**別ページへの遷移**を設定可。4ページ構成のナビに使う。

## 7. レイアウト / スタイル / テーマ

- **キャンバスサイズ**: プリセット or カスタム。**最小 10×10px 〜 最大 幅2000px × 高さ10000px**。
- **グリッド設定**: 最小グリッド 10px。サイズ/パディングを調整し部品配置を揃える。「グリッドにスナップ」で整列。
- **テーマ**: 「テーマとレイアウト」パネルでテーマ選択、または**カスタムテーマ**を作成（画像から配色抽出も可）。系列カラーパレット、グリッド線、チャートヘッダー表示（常時/ホバー時/非表示）等をレポート既定として設定。
- **ヘッダー表示**: 閲覧モードのレポートヘッダー（タイトル・共有/編集ボタン）の挙動。「最初は非表示（ホバーで表示）」等。
- **配置とサイズ**: 部品を選択してドラッグ/数値でサイズ指定。背景・境界線・角丸・影などスタイル設定。ページごとにナビゲーション（左/上タブ等）を設定可。

## 8. 共有・埋め込み・スケジュール配信

- **閲覧共有**: 「共有」から特定ユーザー/グループ、リンクを知る全員、一般公開などのアクセスレベルを設定。閲覧者/編集者の区別。
- **埋め込み (iframe)**: 「共有 → レポートを埋め込む」で**iframe 埋め込みコード**を取得。埋め込みを有効化する必要あり。iframe 対応の任意サイト/アプリに貼れる。
- **PDF エクスポート**: 全ページを PDF 出力。**現在のフィルタ状態が反映**されたスナップショット。
- **メール配信スケジュール**: 「スケジュール配信」で頻度・時刻・宛先を設定し、**PDF 添付＋ライブ版リンク**を定期送信。

## 9. コミュニティビジュアル（サンキー/ワードクラウド/ファネル等）

- **追加方法**: レポート編集画面で「グラフを追加」の隣にある**コミュニティビジュアルとコンポーネント**アイコン → ギャラリーから選択、または開発者の**マニフェスト(gs:// パス)**を指定して読み込む。
- 任意のデータソースからデータを受け取り、JavaScript + Canvas/DOM で描画する仕組み。
- 代表例:
  - **サンキー (Sankey)**: 2つ以上のディメンション間のフロー/関係。線幅が量に比例（検索キーワード→カテゴリ等の流れに有効）。
  - **ワードクラウド (Word Cloud)**: テキスト出現頻度を視覚化（検索キーワードの頻度表示に好適）。
  - **ファネル (Funnel)**: 段階ごとの減衰。近年は標準に近い形でも利用可。
- **注意**: サードパーティ製のためサポート/セキュリティレビューは各自判断。データがビジュアル提供元に渡る場合がある点に留意。

## 10. 制約・注意点

- **行数上限**: コネクタにより異なる（概ね最大 100万行程度、コネクタによってはより低い）。テーブルチャートは行制限を設定でき、PDF/配信時は表示行が制限される（Looker の例で 1テーブル 5万行・ダッシュボード合計 20万セル等の制約が入る場合あり）。
- **アップロード系データ**: CSV 等の直接アップロードは**1データセット 100MB / ユーザー合計 2GB**の上限。
- **Extract**: 100MB/抽出（第1節参照）。
- **キャッシュは保証されない**: 鮮度設定内でも BigQuery に再クエリが飛び得る。コスト/クォータに注意。パフォーマンスは Extract / BI Engine で担保。
- **描画**: カテゴリ/系列が多すぎると円グラフ等は見づらい。行数を集計・上限設定で抑える。
- **無料版**: 基本機能（レポート作成/共有/多くのコネクタ）は無料。**Looker Studio Pro**は組織管理・SLA・チームワークスペース等の追加機能（本手順書の標準機能は無料版で構築可能）。

## 確認事項（実機で要検証）

1. **日本の都道府県塗り分け（最重要）**: 公式ドキュメントは日本の都道府県を第1レベル国内地域としてサポートと明記し、`JP-13`(東京)/`JP-23`(愛知) を例示。基盤の Google GeoChart も `resolution:'provinces'` で日本対応。**したがって都道府県レベルの塗り分けは可能と判断**。ただし過去に「非US地域の ISO-3166-2 が描画されない」というコミュニティ報告もあるため、**必ず実データで検証**すること。検証ポイント:
   - `region_code`(例 `JP-13`) と **英語都道府県名**(例 `Tokyo`) のどちらが確実にジオコーディングされるか（両方試す。**ローマ字/英語名推奨、日本語名は不確実**）。
   - Geo チャートの**ズームエリアを「日本」/「地域」に設定**しないと都道府県が表示されない点。
   - 塗り分けが不安定な場合は**緯度経度によるバブルマップ（Google マップ）**にフォールバック。
2. **`LATITUDE` / `LONGITUDE` 関数の有無**: 緯度経度データ型から成分を取り出す関数として存在すると思われるが、公式 Function list（support.google.com/looker-studio/table/6379764）で正確な関数名・引数を確認すること。
3. **標準チャートとしてのサンキー/ファネル/ウォーターフォール**: ドキュメントの種類一覧に登場するが、標準搭載かコミュニティビジュアルかは編集画面で確認。
4. **無料版とProの機能差**: 本リファレンスの構築手順は無料版前提。Pro 固有機能は使用しない想定。
